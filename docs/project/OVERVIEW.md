# AI Smart Civic Services

An AI-powered civic complaint and service-management platform. Citizens report local problems in plain
language; the system understands the complaint, classifies it, judges its urgency, routes it to the right
department, and gives service teams a triage workspace and a statistics dashboard that explains what the data
actually means.

Built for the SMIT / OpenBook AI **Problem-Solving Hackathon**, targeting all three batch benchmarks at once:
advanced AI, statistics, and object-oriented architecture.

## The problem

Karachi residents deal with broken streetlights, uncollected garbage, potholes, water leaks and choked drains
every day. Reporting is fragmented, and service teams are left guessing which of hundreds of free-text
complaints is urgent and whose job it is. **This project turns an unstructured sentence into structured,
prioritised, routed, actionable work** — and then measures how well the city is responding.

## What it does

**For citizens**
- Report a problem in plain English, Urdu-flavoured English, or Roman Urdu — with location and an optional photo
- Watch the AI read and classify the complaint live during submission
- Get a reference code and track progress without ever creating an account

**For service teams**
- A triage inbox with search, faceted filters, sorting and pagination
- Per-complaint AI panel: category, priority, summary, suggested department, confidence, and **which AI tier
  produced it**
- Duplicate detection — "this looks like CIV-8F3K2M reported 200m away three days ago"
- Status workflow with a full audit timeline and automatic department routing
- An analytics dashboard, and a natural-language assistant that answers questions about the complaint data

## The AI

Three tiers, tried in order, so the system never has a single point of failure:

1. **DeepSeek `deepseek-v4-flash`** — JSON-mode classification, priority, summary, department and keyword
   extraction from the raw complaint text.
2. **A locally trained scikit-learn model** — TF-IDF (word + character n-grams) into a calibrated LinearSVC,
   trained on a generated, evaluated civic-complaint dataset. Runs with no network and no API key.
3. **A deterministic rule engine** — weighted keywords in English and Roman Urdu plus emergency heuristics.

Every result records which tier produced it, and the UI shows that as a badge. Complaint submission never
blocks on the LLM: the complaint is saved immediately and enriched in a background task, so an API outage can
delay analysis but can never lose a citizen's report.

Model evaluation, worked examples and an honest discussion of limitations:
[AI testing evidence](../AI_TESTING_EVIDENCE.md).

## The statistics

Resolution times are strongly right-skewed, so the dashboard leads with the **median and IQR**, not the mean —
and says why in plain English. It computes mean, median, mode, min, max, range, variance and standard
deviation (sample, `ddof=1`), frequency distributions with the modal category, quartiles with **Tukey fences**
that surface abnormally slow complaints as an actionable list, rolling-average trends, and a chi-square test of
independence between category and priority that reports its own validity assumptions.

Every figure is paired with a sentence explaining what it means, generated by a deterministic rules engine —
never by the LLM, so a statistic can never be hallucinated.

## Running it locally

```bash
# Backend  → http://localhost:8000  (docs at /docs)
cd civic-backend
cp .env.example .env          # add DEEPSEEK_API_KEY when you have one; optional
uv sync
uv run python -m scripts.seed --reset
uv run uvicorn app.main:app --reload

# Frontend → http://localhost:5173
cd civic-frontend
cp .env.example .env
npm install
npm run dev
```

Neither a DeepSeek key nor Postgres is required to run locally: the app falls back to SQLite and to the
offline AI tiers.

## Deployment
